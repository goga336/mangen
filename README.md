# mangen

Утилита командной строки для генерации манифеста каталога (список пар из имени/пути файла и значения его хэш-суммы) в стиле UNIX-утилит. Написана на языке C.
В качестве хэш-функции была выбрана официальная реализация SHA-256 из RFC 6234 (IETF), без модификаций.

## Сборка

Для сборки и полноценной работы проекта требуются следующие инструменты:

*   **Компилятор C** (`gcc` или `clang`)
*   **GNU Make** (`make`)
*   **Doxygen**  — используется  для генерации HTML-документации по исходному коду.

    make            # сборка
    make clean      # удалить артефакты сборки
    make test       # запустить end-to-end тесты
    make doc        # сгенерировать HTML-документацию в doc/html/

## Использование

    mangen [OPTION]... [DIR_PATH]

Если `DIR_PATH` не задан, генерируется манифест для текущего каталога.

### Опции

| Опция          | Действие                                                       |
|----------------|----------------------------------------------------------------|
| `-h`           | Показать справку и выйти.                                      |
| `-v`           | Показать версию (git commit hash) и выйти.                     |
| `-e FILE_NAME` | Исключить из манифеста все файлы и каталоги с именем `FILE_NAME`. |
| `-E PATTERN`   | Исключить файлы/каталоги по glob-паттерну (`.` — любой один символ, `*` — любая последовательность). |
| `-i`           | Добавить в конец манифеста строку контроля целостности.        |
| `--verify`     | Проверить целостность манифеста, читая его из `stdin`.         |

### Примеры

    # Простой манифест текущего каталога
    ./mangen

    # Манифест каталога /etc, исключая файлы с именем "hosts"
    ./mangen /etc -e hosts

    # Исключение по glob-паттерну: все файлы *.log
    ./mangen /var/log -E '*.log'

    # Генерация манифеста с контролем целостности
    ./mangen /etc -i > manifest.txt

    # Проверка целостности ранее созданного манифеста
    cat manifest.txt | ./mangen --verify

## Формат вывода

    file1.txt : ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad
    subdir/file2.txt : 5891b5b522d5bd08b4f8bf3c2d17e0a5...

Пути в выводе указываются **относительно `DIR_PATH`** (или текущего каталога, если путь не передан).

## Контроль целостности манифеста

При передаче манифеста через ненадежный канал связи (например, по сети или через публичные файлообменники) существует риск, что злоумышленник или случайный сбой изменит содержимое. Для защиты от этого утилита поддерживает режим контроля целостности.

### Генерация с защитой (`-i`)

Если при создании манифеста указать флаг `-i` (integrity), в конец файла добавляется специальная строка с контрольной суммой всего манифеста:

    file1.txt : ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad
    subdir/file2.txt : 5891b5b522d5bd08b4f8bf3c2d17e0a5...
    --- integrity: 42e93b9bb77d8a73e8412111b8f3d6befab66bf48fdcdefa80bb111819aa0cb1

Строка `--- integrity:` содержит SHA-256 хэш от **всего текста манифеста**, который идет до неё (включая все переводы строк).

### Проверка целостности (`--verify`)

Чтобы проверить манифест, полученный по сети, используется флаг `--verify`. В этом режиме утилита читает манифест из стандартного потока ввода:

    cat manifest.txt | ./mangen --verify

Утилита автоматически отделяет тело манифеста от строки `--- integrity:`, пересчитывает хэш тела и сравнивает его с указанным в конце файла.

Код возврата:
- `0` — манифест не изменен (хэши совпадают).
- `1` — манифест поврежден или подделан (хэши не совпадают).
- `2` — ошибка формата (отсутствует строка `--- integrity:` или файл пуст).

**Ограничения метода:** Данный метод защищает от случайных искажений (бит-флипы при передаче, обрывы соединения) и от непреднамеренных изменений. Однако он не защищает от злоумышленника, который имеет доступ к каналу: если он изменит файл в манифесте, он сможет пересчитать и хэш всего манифеста. Для защиты от подделки требуется электронная подпись (например, GPG) или HMAC с секретным ключом.

## Архитектура

Код разделён на модули с одной ответственностью:

| Файл                        | Назначение                                              |
|-----------------------------|---------------------------------------------------------|
| `src/main.c`                | Точка входа, парсинг аргументов, диспетчеризация.       |
| `src/walk.c` / `inc/walk.h` | Рекурсивный обход каталога через `opendir`/`readdir`.   |
| `src/hash.c` / `inc/hash.h` | Вычисление SHA-256 для файла и форматирование вывода.   |
| `src/regexp.c` / `inc/regexp.h` | Реализация glob-матчера для опции `-E`.              |
| `src/rfc6234/sha.h`         | RFC 6234: заголовки и типы SHA.                         |
| `src/rfc6234/sha-private.h` | RFC 6234: внутренние макросы SHA_Ch/SHA_Maj.            |
| `src/rfc6234/sha224-256.c`  | RFC 6234: реализация SHA-224 и SHA-256.                 |

Файлы RFC 6234 не модифицируются — это каноническая IETF-реализация.

## Алгоритм хэширования

В качестве алгоритма хэширования выбран SHA-256 (FIPS 180-4) в виде официальной реализации из RFC 6234 (IETF Trust, BSD-лицензия). Данный выбор обусловлен тем, что устаревшие алгоритмы, такие как MD5 и CRC32, уязвимы к коллизиям и не подходят для надежного контроля целостности данных. SHA-256 на сегодняшний день является стандартом для подобных задач. Реализация из RFC 6234 была выбрана потому, что она официально опубликована IETF и прошла рецензирование, в отличие от множества сторонних библиотек. Для самопроверки корректности работы алгоритма можно использовать известный NIST-вектор.

## Тесты

End-to-end тесты написаны на Bash (`tests/`). Запуск:

    make test

Тесты проверяют:
1. Вывод справки (`-h`) и код возврата.
2. Генерацию манифеста для текущего каталога (дефолтное поведение).
3. Исключение файла через `-e` (файл не попадает в вывод).
4. Исключение директории через `-e` (вложенные файлы не попадают в вывод).
5. Исключение по glob-паттерну через `-E` (с поддержкой `.` и `*`).
6. Обработку ошибок (неизвестный флаг, несуществующий путь, файл вместо каталога).
7. Проверку контроля целостности (режимы `-i` и `--verify`).

## Документация (Doxygen)

Конфигурация Doxygen в `Doxyfile`. Запуск:

    make doc

Для просмотра документации достаточно открыть `doc/html/index.html` в браузере.

Если Doxygen не установлен:

    sudo apt install doxygen     # Debian/Ubuntu
    sudo pacman -S doxygen       # Arch Linux

## Ограничения

Символические ссылки, FIFO, сокеты, устройства пропускаются — их хэширование лежит вне области применения.
